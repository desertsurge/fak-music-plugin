# Fak Music 发布候选版设计

## 目标

将现有 Fak Music Manifest V3 MVP 推进到可验收的发布候选版：播放失败可恢复，目录刷新行为可预测，Popup 交互闭环，测试和浏览器证据完整。当前远程目录地址和 fallback 音频继续作为开发样例，不在本轮引入新的真实音乐供应商。

## 范围

### 包含

- 修复卡片播放/暂停、备用地址失败后的自动跳过和错误事件重复处理。
- Service Worker 初始化后的首次远程目录刷新、定时刷新和缓存回退。
- Popup 类型筛选、刷新失败反馈、播放失败反馈和窄窗口布局验证。
- 目录、播放、消息路由和 Popup 行为测试。
- `dist/` 扩展加载验证，桌面和窄窗口截图，并通过 `cc-connect --image` 发送到当前飞书会话。
- 补充开发样例、许可证边界和发布前检查文档。

### 不包含

- 接入网易云、QQ 音乐等需要登录、签名、付费或 DRM 的服务。
- 建立独立的音乐目录生成仓库和真实数据源自动抓取流水线。
- 用户自定义远程源编辑器。
- 本轮重写整个播放器架构或更换 UI 设计语言。

## 架构与数据流

Popup 继续只负责呈现状态和发送 `RuntimeMessage`。Service Worker 负责目录状态、播放队列、错误恢复和缓存；Offscreen Document 继续持有唯一的 `HTMLAudioElement`。目录刷新通过 `fetchRemoteCatalog` 注入请求地址和 fetcher，成功后原子替换 catalog，失败时不修改现有 catalog。

播放一次只允许一个活动加载请求。音频错误事件通过当前 item、候选地址索引和加载令牌校验，避免旧请求的迟到事件推进新队列。候选地址耗尽后调用下一项；如果队列为空则显示错误状态。

## 用户交互

- 卡片按钮在当前条目播放时显示暂停并发送 `TOGGLE_PLAY`，其他条目发送 `PLAY_ITEM`。
- 筛选按钮打开轻量类型筛选菜单；选择“全部、电台、单曲”后与搜索条件组合过滤。
- 刷新按钮显示加载中、成功同步或失败但保留当前目录三种状态。
- 播放完全失败时显示错误状态和重试操作，同时自动尝试下一项。

## 测试策略

- 先为每个缺陷写可复现的失败测试，再修改生产代码。
- 单元测试覆盖候选地址、队列跳过、目录刷新和状态转换。
- Popup 测试覆盖筛选、卡片播放/暂停和刷新错误状态。
- 构建门禁为 `npm run test:run`、`npm run build`。
- 浏览器验收覆盖扩展加载、首屏、筛选、搜索、播放控制、错误状态、窄窗口和无横向溢出。
- 每次 UI 改动必须保存截图，并使用 `cc-connect send --image <path>` 发送到飞书；发送失败必须记录原因。

## 验收标准

1. 首次启动展示 fallback，并在后台发起一次远程目录刷新。
2. 远程响应错误、超时或格式错误不会覆盖最后一次有效目录。
3. 当前卡片的暂停操作真正暂停，源全部失败后自动进入下一项。
4. 所有新增行为都有自动化测试，测试和生产构建通过。
5. `dist/` 可加载，桌面和窄窗口截图无明显布局错误，并已发送到飞书。
